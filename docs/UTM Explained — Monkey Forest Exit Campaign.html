01

What UTM Actually Is

UTM stands for Urchin Tracking Module. It is a set of query parameters you add to the end of a URL so analytics tools can tell you where each visitor came from.

It was created by a company called Urchin, which Google acquired in 2005 — that acquisition became Google Analytics. The name stuck.

The one-sentence version

UTM tags are URL suffixes that tell your analytics which specific link, QR code, email, or ad brought each visitor — without needing any login or cookie.

02

The 5 Standard UTM Parameters

There are exactly five. Every one is optional, but the more you use consistently, the more you learn. They always start with utm_.

The five UTM parameters and what they answer
Parameter Question it answers Example value
utm_source Where did they come from? qr_exit
utm_medium How did they get here? qr
utm_campaign Which campaign? monkey_forest_exit
utm_term Which keyword? (paid search only) restaurant+ubud
utm_content Which variant? (A/B test, which button) hero_cta
For this campaign specifically

You will mainly use utm_source (which QR placement), utm_medium=qr (always "qr"), and utm_campaign=monkey_forest_exit (always the same). Add utm_content only when testing A/B creative variants.

03

What It Looks Like in a URL

The ? starts the query string. Each key=value pair is separated by &. Order does not matter. 

https://tropicalviewubud.com/after-monkey-forest
  ?utm_source=qr_exit
  &utm_medium=qr
  &utm_campaign=monkey_forest_exit
  &utm_content=gate_sticker

Anatomy of the URL

https://tropicalviewubud.com → /after-monkey-forest → ?utm_source=qr_exit → &utm_medium=qr → &utm_campaign=...
  • Domain — the website itself
  • Path — /after-monkey-forest, the campaign page
  • ? — marks the start of query parameters
  • & — separates each parameter
  • utm_* — the attribution tags your analytics reads

Why This Campaign Needs UTM

In the playbook, every physical QR placement gets its own utm_source. Same landing page, same offer — different tracking label.

Without UTM vs with UTM

Without UTM

"200 people visited the campaign page this week."

You have no idea which QR code, which flyer, or which driver brought them — so you cannot decide where to print more.

With UTM

"142 from the exit sticker. 40 from the ticket. 18 from the driver dashboard."

Now you know the exit sticker is worth reprinting and the driver dashboard is worth pitching to more drivers.

05

UTM vs Promotion Code

They look similar but do different jobs. You will use both in the same campaign.

Two tracking mechanisms, two purposes
UTM Promotion code
Lives in The URL query string Database + QR + URL
Purpose Marketing attribution Voucher redemption + anti-abuse
Persisted where Your analytics tool Your promotion_redemption table
Example utm_source=qr_exit MF-EXIT-01
Why both

UTM tells you where the visitor came from. The promotion code proves they actually redeemed the offer. Together they let you cross-check: did the analytics-reported source match the voucher redeemed?

06

How UTM Flows Through the App

From the moment a tourist scans a QR code to the moment you read the weekly report, here is the full path.

Tourist scans QR→ URL carries utm_source=qr_exit→ Nuxt route reads query→ useCampaign() returns source→ Every tracking event includes it→ Report: "qr_exit = 22 claims"

In code, it looks like this

// Composable resolves the source from the URL
const { utmSource } = useCampaign()

// Passed into the WhatsApp URL builder
const whatsappUrl = computed(() =>
  buildClaimUrl({
    offerTitle: offer.value?.title,
    utmSource: utmSource.value,  // e.g., "qr_exit"
    locale: locale.value,
  })
)

// Every claim click reports the source
useTrackEvent('wa_claim_click', {
  source: 'hero',
  utm_source: utmSource.value,   // Attribution travels with the event
})

The same utmSource value appears in every tracking event and in the WhatsApp pre-filled message (src: qr_exit). That is how the analytics dashboard and the restaurant's redemption log stay in sync.

07

Common Beginner Mistakes

  • Case sensitivity. utm_source=QR_Exit is a different source from utm_source=qr_exit to your analytics tool. Always lowercase.
  • Inconsistent naming. qr-exit, qr_exit, and qrexit all look like separate sources. Pick one convention and lock it before printing any QR codes.
  • Spaces inside values. Must be URL-encoded as %20 or +. Better: use underscores or dashes instead.
  • Using UTM on internal links. Linking from your own homepage to your own menu with ?utm_source=homepage will overwrite the original source in Google Analytics. UTM is for inbound traffic only.
  • Forgetting UTM on QR codes. Very common. Without it, all QR traffic looks like "direct" traffic and you learn nothing about which placement works.
  • Different UTM on the same placement. If your exit sticker has qr_exit but the printed backup has exit_qr, your data splits into two buckets and looks like two underperforming sources.
08

Naming Convention — Locked

Copy this exactly. Do not improvise. Consistency is the entire point of UTM. 

utm_source   = qr_exit | qr_ticket | qr_guesthouse |
               qr_driver | guide_card | sticker_table

utm_medium   = qr

utm_campaign = monkey_forest_exit

utm_content  = <creative variant>    (optional)
               e.g., combo_a  vs  combo_b
Rule of thumb

Lowercase. Underscores between words. No spaces. No capital letters. If you ever hesitate, look at the table in Section 4 — that is the source of truth.

Full example URLs

https://tropicalviewubud.com/after-monkey-forest?utm_source=qr_exit&utm_medium=qr&utm_campaign=monkey_forest_exit

https://tropicalviewubud.com/after-monkey-forest?utm_source=qr_ticket&utm_medium=qr&utm_campaign=monkey_forest_exit

https://tropicalviewubud.com/after-monkey-forest?utm_source=qr_driver&utm_medium=qr&utm_campaign=monkey_forest_exit

These three URLs point to the same page with the same offer. Only the utm_source changes. That difference is what makes the report meaningful.
