Why /data and resto.db are not inside /server

Nuxt-Resto-Website · data-docs · 2026-10-15

The question

Why is the /data folder and its resto.db not inside /server?

It is deliberate, for three reasons:

1. Build boundary

Everything under server/ is build input: Nitro bundles it into .output/server/. A live SQLite file inside server/ would either get copied into the bundle (a stale snapshot baked into deploys) or wiped on rebuild. data/ at root sits outside the bundler's reach, so the database survives pnpm build untouched.

2. Runtime writability

The app writes to the DB (orders, reservations, redemption tracking). Deploy targets typically treat the bundled server/ output as immutable/read-only, while a root-level data/ dir can be mounted as a persistent volume. dbName: './data/resto.db' resolves from process cwd in both dev and prod, so the same path works everywhere.

3. Git hygiene

data/*.db* is gitignored as a unit. Inside server/ it would sit next to tracked source files, inviting accidental commits of a binary blob (and merge conflicts on it).

Trade-off

Two top-level data locations (data/ for SQLite, server/data/*.json legacy seeds). The JSON dir is orphaned seed reference only — the clean move is deleting server/data/ once the DB seed is trusted, not moving data/ inward.
