WKPicture component

Image primitive for <picture> + <img> with multi-stage fallback and runtime canvas placeholder. Documentation is based on the current implementation in this folder.

Component: app/components/base/WKPicture.vue  |  Util: app/utils/drawPlaceholderToCanvas.ts

Overview

WKPicture wraps a native <picture> so callers can provide responsive <source> candidates and a guaranteed fallback chain instead of a broken-image icon. It is designed for conversion/marketing surfaces where a missing asset must degrade gracefully while still surfacing developer diagnostics in dev mode.

Current status (from implementation): the source-failure and primary-src-failure paths are wired end-to-end, and a terminal runtime canvas/SVG placeholder is generated when both network images fail. Residual issues remain (see Fixes needed & proposals); this doc calls them out explicitly.

Fallback tiers at a glance

TierRendered URL comes fromWhen chosen
1 (highest)runtimePlaceholderSrc (data URL)After stage C successfully renders a runtime placeholder
2props.fallbackNo effective src, or primarySrcFailed === true
3normalized props.srcNormal case: props.src is non-empty and not marked failed

Implemented in resolvedImgSrc (computed) and driven by handleError state transitions.

Quick start

<script setup lang="ts">
import WKPicture from '~/components/base/WKPicture.vue'
</script>

<template>
  <WKPicture
    src="/images/hero-1200.webp"
    alt="Shaded rice-field seating near Monkey Forest exit"
    fallback="/images/placeholder.svg"
  />
</template>

If /images/hero-1200.webp fails, the component tries fallback. If the fallback also fails, it renders a generated runtime placeholder (canvas → PNG data URL) using the alt text as the title.

How to use (detailed)

Props reference

PropTypeDefaultRequiredBehavior / notes
src string | null undefined No Primary <img src>. Trimmed internally; empty/whitespace-only becomes "no src" and resolves to fallback (tier 2) immediately. Can be used with or without sources.
alt string — Yes Forwarded to <img alt>. Also passed as title to the runtime placeholder generator when stage C runs.
fallback string '/images/placeholder.svg' No Image shown when src is empty or when the primary src fails (stage B). If this URL also fails, stage C renders a runtime placeholder.
sources ImageSource[] () => [] No Responsive candidates rendered as <source> elements inside <picture>. Omitted entirely once any source fails (pictureSourceFailed), for the lifetime of the instance until props change.
sizes string undefined No Forwarded to <img sizes>. Note: <img> has no srcset in this component, so this attribute is a no-op for selection; meaningful sizes belong on ImageSource.sizes per source when used with source srcset.
loading 'lazy' | 'eager' 'lazy' No Forwarded to <img>.
decoding 'sync' | 'async' | 'auto' 'async' No Forwarded to <img>.

ImageSource type

Exported from WKPicture.vue:

export type ImageSource = {
  srcset: string; // required — comma-separated candidate list
  media?: string;  // e.g. "(min-width: 768px)"
  type?: string;   // e.g. "image/webp", "image/avif"
  sizes?: string;  // slot size hint for this source
};
Mirrors native <source> attributes 1:1. Ordering of sources follows browser <picture> selection rules (first matching source wins) — order intentionally.

Example: basic <img>-only (no sources)

<WKPicture
  src="/images/monkey-forest-exit-1200.webp"
  alt="Exit path at Monkey Forest"
  fallback="/images/placeholder.svg"
/>

Behavior:

  • src loads → shown.
  • src 404s → stage B sets primarySrcFailed, resolvedImgSrc becomes fallback, <img> retried.
  • fallback 404s → stage C generates a runtime placeholder data URL with alt as title.
  • src is empty/null/whitespace → fallback is used immediately (no error event required).

Example: responsive <picture> sources

<script setup lang="ts">
import WKPicture, { type ImageSource } from '~/components/base/WKPicture.vue'

const heroSources: ImageSource[] = [
  {
    srcset: '/images/hero-768.webp',
    media: '(max-width: 768px)',
    type: 'image/webp',
  },
  {
    srcset: '/images/hero-1200.webp',
    media: '(max-width: 1200px)',
    type: 'image/webp',
  },
  {
    srcset: '/images/hero-1536.webp',
    media: '(min-width: 1201px)',
    type: 'image/webp',
  },
]
</script>

<template>
  <WKPicture
    :sources="heroSources"
    src="/images/hero-1200.webp"
    alt="Reward after visiting Monkey Forest"
    fallback="/images/placeholder.svg"
  />
</template>

Behavior: the browser selects one matching <source> (or falls through to <img src> if none match/supported). On a selected-source 404, stage A disables all sources for this instance (pictureSourceFailed = true) and re-keys the <img> so selection re-runs against <img src>. Subsequent breakpoints will not use <source> entries until props.src or props.sources changes (watcher reset).

Order matters: <picture> picks the first matching source. The example above tiles ranges in ascending order. Overlapping/conflicting media queries can make the "wrong" candidate win — this is browser behavior, not a component bug.

Example: hero / LCP-oriented usage

<WKPicture
  class="hero__image"
  :src="heroSrc"
  :sources="heroSources"
  :alt="t('campaign.hero_alt')"
  loading="eager"
  decoding="async"
  fallback="/images/placeholder.svg"
/>
  • Set loading="eager" for above-the-fold/LCP imagery.
  • alt should be meaningful (and localized if the image conveys content) — it is also used as the runtime placeholder title.
  • Not currently supported as props: fetchpriority, width, height. These matter for LCP prioritization and CLS reservation on 4G; see proposed fixes if needed.

Real consumer in repo: app/components/monkey-forest/CampaignHero.vue (currently in test state with non-existent *x.webp paths and loading="lazy" — treat as integration reference, not a production-ready example).

Example: dynamic props & resets

<script setup lang="ts">
import { ref } from 'vue'
import WKPicture from '~/components/base/WKPicture.vue'

const src = ref('/images/a.webp')
function swap() { src.value = '/images/b.webp' }
</script>

<template>
  <WKPicture :src="src" alt="Dynamic image" />
  <button @click="swap">Swap</button>
</template>

Reset behavior: a watcher on [props.src, props.sources] (non-deep, non-immediate) resets:

  • runtimePlaceholderSrc = ''
  • primarySrcFailed = false
  • failedImgSrc = ''
  • pictureSourceFailed = false
  • retryKey = 0

So after a failure, changing src (or replacing the sources array reference) gives the component a clean slate to try again.

Reference identity matters: because the watcher is not deep, mutating the same sources array in-place (e.g. push, [0].srcset = ...) or passing a new inline array literal on every render may not trigger the intended reset. Pass a stable array and replace its reference when the set of sources changes.

Placeholder & runtime fallback

Static fallback file (tier 2): default is /images/placeholder.svg. Override with fallback when a domain-specific placeholder is preferred.

Runtime placeholder (tier 3, terminal): if the URL that ends up being requested still fails at stage C, handleError calls:

const placeholderSrc = await drawPlaceholderToCanvas(el, { title: el.alt });

The util (app/utils/drawPlaceholderToCanvas.ts) generates an SVG label, decodes it through an Image, draws to a <canvas>, and returns canvas.toDataURL('image/png'). Defaults inside the util: background #efefef, title format uppercase, title color #7a7a7a, canvas size derived from the element (with fallbacks/clamps).

Why async: stage C awaits image decode and canvas work, so it includes a stale-input guard — if props.src, props.fallback, or failedImgSrc changed while awaiting, the generated placeholder is discarded to avoid flashing a stale result.

Feature list

A/B/C fallback chain (handleError)

StepTrigger (as implemented)State changesEffect
Guard 0 runtimePlaceholderSrc is set and imgUrl (el.currentSrc) equals it none Logs error and returns. Prevents infinite regeneration if the generated placeholder itself fails to load.
Stage A
source failed		 props.sources.length > 0 && !pictureSourceFailed && imgUrl !== el.src pictureSourceFailed = true, retryKey++ Removes <source> elements (v-if off) and recreates <img> via :key so browser re-runs selection against <img src>.
Stage B
primary src failed		 primarySrcAtFailure (trimmed props.src) is non-empty && imgUrl === el.src && el.src !== fallbackUrl failedImgSrc = imgUrl, primarySrcFailed = true, retryKey++ resolvedImgSrc switches to props.fallback; <img> retries with fallback URL.
Stage C
last resort		 Anything not handled by A/B (fallback failed, no primary src, or other) failedImgSrc = imgUrl; on success + stale-check pass: runtimePlaceholderSrc = dataUrl, retryKey++ Generates runtime placeholder (PNG data URL). Rendered at tier 1 of resolvedImgSrc.

URL comparison model: imgUrl is el.currentSrc (absolute). Stage A/B compare against el.src (absolute DOM-reflected URL). Stage B compares the fallback by normalizing it with new URL(fallbackSrc, el.ownerDocument.baseURI).href so relative fallbacks can be compared correctly.

Template highlights: <source> list is v-if="shouldRenderPictureSources" with :key="i". <img> binds :key="retryKey", :src="resolvedImgSrc", required :alt, optional sizes/loading/decoding, and hooks @error="handleError", @load="handleLoad".

Prop-change reset: watcher on () => [props.src, props.sources] resets all failure/runtime state and retryKey to 0.

Runtime placeholder util (drawPlaceholderToCanvas.ts)

  • API: drawPlaceholderToCanvas(img: HTMLImageElement, options?: PlaceholderOptions): Promise<string>
  • Options: backgroundColor, title, titleFormat ('uppercase' | 'lowercase' | 'title-case'), titleColor.
  • Size inference: uses img.getAttribute('width'|'height'), clientWidth/Height, and a 3:2 aspect fallback; clamps width 120..2400, height 120..1600.
  • Rendering: creates SVG markup with escaped/wrapped title, loads it as a blob URL into an Image, draws to a 2D canvas, returns PNG data URL, revokes object URL in finally.
  • Failure modes: throws on missing canvas context, image decode error, or empty toDataURL result.

Gotchas & warnings

Browser <picture> semantics (relevant to this component)

  • <picture> selects a resource once per selection pass. el.currentSrc is the browser-chosen (absolute) URL; <img src> is not an automatic error fallback.
  • A <source> 404 fires error on the <img> but does not auto-fall back. Inputs must change to force reselection — WKPicture does this by removing sources (pictureSourceFailed) and recreating the <img> (retryKey++).
  • <img> must be the last child of <picture>. The component satisfies this; if callers misuse slots in a fork, selection breaks.
  • Source order and media ranges are the caller's responsibility. Overlaps, gaps, or wrong ordering can select unexpected candidates.
  • type support is browser-evaluated. Unsupported types (e.g. AVIF in older browsers) are skipped without an error event.

Component-specific behavior

  • One source failure disables all sources for the instance. After stage A sets pictureSourceFailed, the component stops rendering every <source> until props.src or props.sources identity changes. This is intentional for simplicity but means one bad breakpoint degrades the rest.
  • Failure is sticky within a prop state. There is no automatic retry on network recovery; only a prop change (watcher) resets state.
  • sizes prop on <img> is effectively inert here. The <img> has no srcset, so <img sizes> does not influence selection. Use ImageSource.sizes for source candidates when applicable.
  • sources watcher is not deep and compares references. In-place mutation or inline array literals can skip the reset, leaving stale failure flags against new content. Prefer replacing the array reference.
  • No width/height/fetchpriority/class-passthrough prop API. Layout sizing/priority must be handled via CSS/attributes outside the declared prop surface today (attributes may fall through depending on usage, but are not part of the contract). See fixes.
  • Alt text becomes placeholder title. Stage C passes { title: el.alt } to the util; very long or missing alt strings affect the generated placeholder's readability.
  • Runtime placeholder is a PNG data URL. Large dimensions increase string size; this is a terminal fallback, not a primary delivery format.
  • Stage B increments retryKey even though src changes. Redundant but harmless given resolvedImgSrc flips from primary to fallback.

Dev console & diagnostics

  • console.error/warn/log calls are gated by import.meta.dev in handleError/handleLoad.
  • Stage A emits an error including the failed URL and the retry target (resolvedImgSrc at that moment).
  • Stage B/C emit an error for the failed resolvedImgSrc.
  • Stage C emits console.warn ("Both image sources failed; rendering a runtime placeholder.") on success path and console.error if placeholder rendering throws.
  • handleLoad logs the loaded URL in dev, including full data:image/png;base64,... strings for runtime placeholders — this can be very noisy.
  • On a broken image, the browser may also emit its own network/console errors (404) independent of component logging.

Fixes needing implementation (with proposed fixes)

The items below are grounded in the current code. Each includes impact, location, and a concrete proposed change. Severity is about correctness/robustness for a production funnel, not just style.

High / correctness

High 1. Guard 0 keys on el.currentSrc (can miss empty selection) — loop/extra work risk

Where: handleError, guard 0.

Issue: the terminal guard checks imgUrl === runtimePlaceholderSrc.value where imgUrl = el.currentSrc || ''. If the runtime placeholder somehow fails with an empty currentSrc, the guard won't match and stage C may attempt regeneration (retryKey++) repeatedly. el.src reflects the attribute/data URL and is a stable identity check for the active element.

Proposed fix:

// Guard 0 — terminal: runtime placeholder itself failed
if (runtimePlaceholderSrc.value && el.src === runtimePlaceholderSrc.value) {
  if (import.meta.dev) {
    console.error('[WKPicture] Runtime placeholder image failed to load.');
  }
  return;
}

High 2. new URL(fallbackSrc, ...) is outside try — possible unhandled rejection

Where: stage B, before the if that decides stage B vs C.

Issue: handleError is async. A malformed/unsupported props.fallback (or an unexpected base URI edge case) can throw synchronously from new URL(...), resulting in an unhandled promise rejection and no fallback progression.

Proposed fix: compute fallbackUrl defensively inside a try/catch and degrade to stage C on failure.

const primarySrcAtFailure = normalizedImgSrc.value;
let fallbackUrl = '';
try {
  fallbackUrl = new URL(props.fallback, el.ownerDocument.baseURI).href;
} catch {
  // Malformed fallback URL — skip stage B comparison and fall through to stage C.
  fallbackUrl = '';
}

if (primarySrcAtFailure && imgUrl === el.src && fallbackUrl && el.src !== fallbackUrl) {
  // stage B...
  return;
}
// stage C...

High 3. Runtime placeholder can render at alt-text/broken-image height (util sizing)

Where: app/utils/drawPlaceholderToCanvas.ts (width/height inference from img.clientWidth/clientHeight and attribute fallbacks).

Issue: stage C runs after an image error. A broken <img> often has a small intrinsic/layout height (e.g. alt-text line height) rather than the intended media box, especially when height is percentage/auto in CSS. That can produce a very thin placeholder instead of a usable block.

Proposed fix (pragmatic): prefer layout/attribute/container signals and enforce a sane minimum aspect-aware height. One approach:

// In drawPlaceholderToCanvas
const attrW = Number(img.getAttribute('width')) || 0;
const attrH = Number(img.getAttribute('height')) || 0;
const rect = img.getBoundingClientRect();
const cssW = Math.round(rect.width) || img.clientWidth || attrW || 0;
const cssH = Math.round(rect.height) || img.clientHeight || attrH || 0;

// If the element collapsed (broken-image/alt-text box), fall back to container or 3:2.
const container = img.parentElement?.getBoundingClientRect();
const baseW = cssW || Math.round(container?.width || 0) || 1200;
const baseH = (cssH && cssH > 40) ? cssH : Math.round(baseW * 2 / 3);

const width = Math.max(120, Math.min(baseW, 2400));
const height = Math.max(120, Math.min(baseH, 1600));

Exact thresholds depend on design intent; the key is to avoid trusting a collapsed broken-image box. Consider also accepting explicit width/height options in the util for callers that know the intended ratio.

High 4. Stage C does not disable sources — extra request in collision/re-entry paths

Where: stage C body (after generating placeholder).

Issue: in some paths (e.g. stage A skipped because imgUrl === el.src in a same-URL collision case, or any future re-entry where pictureSourceFailed is still false), <source> elements may remain in the DOM. Even when resolvedImgSrc becomes a data URL, a surviving matching <source> can win selection and trigger another error before A cleans up — self-healing but wasteful.

Proposed fix: force sources off when committing a terminal placeholder.

if (/* stale checks pass */) {
  pictureSourceFailed.value = true; // ensure no <source> can compete with the placeholder
  runtimePlaceholderSrc.value = placeholderSrc;
  retryKey.value++;
}

Medium / robustness & UX

Medium 5. retryKey starts at 0 — potential duplicate-key warning

Where: const retryKey = ref(0) and template :key="retryKey" on <img>.

Issue: <source> nodes are rendered in a v-if block and the <img> is a sibling under <picture>. Depending on compiled structure, key 0 can collide with compiler-generated fragment/vnode keys in dev warnings. It is low-risk behaviorally but noisy.

Proposed fix:

const retryKey = ref(1);
// watcher reset: retryKey.value = 1;

Medium 6. handleLoad logs full data URLs in dev

Where: handleLoad.

Issue: runtime placeholders produce large base64 PNG data URLs; logging the entire string degrades devtools usability.

Proposed fix:

function handleLoad() {
  if (import.meta.dev) {
    const el = (event?.target as HTMLImageElement | undefined) ?? null;
    // If not changing the signature, just guard on the resolved src:
    const loaded = resolvedImgSrc.value;
    const label = loaded.startsWith('data:')
      ? `${loaded.slice(0, 32)}… (${loaded.length} chars)`
      : loaded;
    console.log(`[WKPicture] image loaded: ${label}`);
  }
}

Alternative: accept the load event parameter: function handleLoad(event: Event) and log (event.target as HTMLImageElement).currentSrc with the same truncation.

Medium 7. No guard for late events from a detached <img>

Where: top of handleError (and optionally handleLoad).

Issue: retryKey++ replaces the element. A late error/load from a detached node is unlikely in the current flow but cheap to ignore.

Proposed fix:

async function handleError(event: Event) {
  const el = event.target as HTMLImageElement;
  if (!el.isConnected) return;
  // ...
}

Medium 8. sources reset depends on reference identity, not deep changes

Where: prop watcher.

Issue: in-place mutations or repeatedly recreated inline arrays can fail to reset failure state or cause unintended churn.

Proposed fix (choose one, document the contract):

// Option A (contract): document "replace the array reference to reset".
// Option B (defensive): deep-watch or watch a serialized key — careful of perf/cycles.
watch(
  () => [props.src, JSON.stringify(props.sources)] as const,
  () => { /* reset */ }
);
// Option C: expose/emit nothing, but normalize in parent composables.

Option A is simplest and consistent with Vue prop patterns; Option B trades simplicity for resilience. Pick one explicitly.

Medium 9. Canvas SVG→raster round-trip is heavier than needed

Where: drawPlaceholderToCanvas.ts.

Issue: the util builds SVG, decodes via Image, draws to canvas, exports PNG data URL. For an on-page placeholder, returning an SVG data URL (or object URL) avoids rasterization cost and scaling blur while keeping implementation simple. Canvas is only necessary if a raster PNG is strictly required.

Proposed fix (if PNG not required):

const svg = `<svg ...>...</svg>`;
return `data:image/svg+xml;charset=utf-8,${encodeURIComponent(svg)}`;

If you keep canvas, consider caching/memoizing by (width,height,title,colors) to avoid regenerating identical placeholders.

Low / cleanup & API

Low 10. failedImgSrc is not used by rendering

Where: state declaration, stage B/C assignments, watcher reset, stage C stale guard.

Issue: it participates in the stale guard (useful) but is otherwise not consumed. Naming/comments imply a broader role than it has.

Proposed fix: either (a) rename to reflect purpose (e.g. lastFailedUrlForGuard) or (b) remove and capture const failedAt = imgUrl locally in stage C, using a separate monotonic token/counter ref if needed for async invalidation.

Low 11. Header/template comments are stale or slightly misleading

Examples: "AppImage.vue" in header comment (line 8) while file is WKPicture.vue; template comment "sources are only considered when we have a valid src" does not match the actual guard (shouldRenderPictureSources only checks sources.length and !pictureSourceFailed); mixed-language inline comments.

Proposed fix: update comments to describe current behavior (A/B/C, resolvedImgSrc tiers, and that source rendering is independent of src presence except through runtime behavior) and keep terminology consistent.

Low 12. ImageSource is exported from a .vue SFC

Issue: works in many setups but can be awkward for type-only imports, tooling, and reuse outside Vue SFC context.

Proposed fix: move to app/components/base/wk-picture.types.ts (or similar) and re-export/import as needed.

// wk-picture.types.ts
export type ImageSource = {
  srcset: string;
  media?: string;
  type?: string;
  sizes?: string;
};

Low 13. Missing performance/layout props: fetchpriority, width, height

Issue: for hero/LCP images on constrained networks, fetchpriority="high" and intrinsic dimensions (width/height) are important for prioritization and CLS prevention. Not exposing them limits the component as a general image primitive.

Proposed fix:

// props
fetchpriority?: 'high' | 'low' | 'auto';
width?: number | string;
height?: number | string;

// template <img>
:fetchpriority="fetchpriority"
:width="width"
:height="height"

Also consider forwarding arbitrary img attributes via useAttrs() / inheritAttrs strategy if the component should remain flexible.

Low 14. primarySrcFailed naming vs behavior scope

Issue: the flag means "declared src failed, so prefer fallback tier" (see stage B). After fallback also fails, stage C takes over with runtime placeholder — the flag remains conceptually true but tier 1 supersedes it. This is fine, but a name like preferFallbackSrc could be clearer. Pure readability; no behavior change required.
